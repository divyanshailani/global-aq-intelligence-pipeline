# 2026-10-22: AQ maintenance moved to a dedicated Instabox VM (aq-ops)

## Why
The agent workspace was wiped four times (Oct15, Oct19/20, Oct21, Oct22), each time dropping the repo, gh login, worker and state files. Owner asked for a self-healing setup on Instabox.

## What
- Dedicated free-tier machine aq-ops (4 vCPU / 8 GiB, 20 GB /data). The three SLM machines are untouched.
- Hourly systemd user timer (minute :07, flock-guarded) runs `aq_supervisor.sh`:
  1. `aq_reliability.py`: missing-launch check (after 13:43 UTC, no same-day daily and none active -> `pipeline_watchdog.py --launch-only`), review of newly completed runs (failed steps, repaired batches, published sha, live last_data_date, DB %, drift), JSONL log in `~/.aq-ops/status.jsonl`.
  2. `aq_nan_recent_repair.py 2`: same NaN-only, rolling 90-day worker with its workflow zero-active and DB guards.
- Secrets: GitHub PAT pushed once over SSH to a 0600 file, consumed by `gh auth login` and deleted. DB creds stay in the 0600 handover file. No Instabox vault or org secrets used. No spend.
- Verified: manual supervisor run succeeded (RELIABILITY_OK, NAN_WINDOWS_DONE 0).

## Not changed
No workflow, model, threshold or pipeline behavior changes.

## Open
Instabox auto-suspends after 1800s idle; a keepalive ping covers it. Agent-side wakes stay as a light review until a timer fire is verified.
