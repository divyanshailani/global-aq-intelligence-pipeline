# Daily reliability and automatic recent weather repair

October 8 run 37775437183 attempt 1 failed the unchanged data contract because Phase 3's three-minute budget left 2,315 recent rows without weather. A manual bounded repair filled those rows with source data and passed the contract. Attempt 2 instead failed twice on the Phase 2 clean-data query, with SSL connection closure after roughly four minutes.

The clean-data query filtered datetime_local, while existing time indexes use datetime_utc; a fleet-wide ORDER BY required a large blocking sort before rows returned. The fix adds an indexed UTC floor with a one-day timezone buffer, retaining the exact local-date predicate, and streams unsorted results in 20,000-row reads. Existing feature daily pivots sort by date. Added connection keepalives. No feature/model/threshold change, no new index or storage allocation. Live 20-station streamed validation returned 1,047,311 rows in 25 seconds without disconnect.

Before the contract, the daily workflow now runs a separate bounded recent weather repair: October-current rolling five-day UTC window, 40-station batches, forecast API only (including GB), finite-only weather values and nonempty-hour AOD averages. Existing finite cells are preserved and checked; no fabricated zero or archive-weather request. DB below 28 GiB and no other active writer required; shared workflow concurrency serializes production. Maximum 125 batches / 10 minutes. Source or budget failure stays a real failed run and alerts; repaired coverage gaps reach the unchanged contract before a failure email is generated. Successful repairs are logged in job output and job summary, and recent derived weather features are recomputed.

Validation: source-routing/bounds/finite-cell regression tests and mocked streaming-read test pass. Live repair test had no missing weather and issued no source requests. Repository static checks passed except a pre-existing inventory gap for five unrelated research/backfill scripts. No pytest installation was available, so direct test functions were used. Daily success remains to be verified on the patched workflow.
